# eHome EMS b13 — design QA

## Scope

User reference: large entity value above a smooth colored curve with a subtle filled area. Home consumption must use solar + signed grid − electrical battery charge + discharge, including all household loads.

## Visual checks

Chromium fixture at 1440×1600 and 390×844: entity curves have the requested colored gradient area, rounded line and explicit six-hour/five-minute-average label. Missing history is never fabricated and gaps are not connected. All values keep at most two decimals. Existing flow tiles, day/night house, 10 W threshold and mobile layout are preserved.

Conso Maison is used consistently in the overview, central flow and configuration shortcuts. A collapsible calculation diagnostic shows the result, each signed contribution, entity, age and failure reason. Mobile source rows stack and wrap. The home source field is disabled in calculated mode; the signed/separate grid selector and freshness setting explain their behavior. No physical equipment actions are added.

Evidence: artifacts/panel desktop/mobile, flow, home-balance, Today, loads and storage screenshots generated by scripts/validate_panel_browser.cjs. Unit checks cover the reference 1,200 W balance, import/export signs, two batteries, included water heater/EV, missing/invalid sources, explicit age-check disable and listener cleanup. Real HA matrix validates the same calculation through scoped websocket configuration and source events while preserving entity IDs.

## Intentional limits

Source powers must cover the same AC boundary. A pack/DC channel cannot guarantee the accuracy of an AC balance. User-installed sensors, reporting schedules and physical RPi performance cannot be verified from a simulated fixture. Existing sensors selected by the user are retained as-is and must include all household loads.
